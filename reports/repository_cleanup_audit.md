# FraudShield ML Repository Cleanup Audit

This report is a precise, evidence-based deletion plan following a complete read-only repository audit. It identifies development leftovers, caches, and obsolete files while preserving all necessary production utilities, notebooks, and model artifacts.

## A. Complete Inventory Overview
- **Git History**: Tiny footprint (`1.20 MiB` loose, `2.62 KiB` packed). No accidental large blobs (.env, databases, zip bundles) have been committed.
- **Data Hygiene**: The raw PaySim datasets (`data/raw/`) and Parquet extracts (`data/processed/`) are correctly untracked/ignored.
- **Empty Directories**: One empty directory was identified: `artifacts/runs/20260828_215203_196a70`.

## B. Generated Cache Files
All typical Python and framework cache directories exist but are correctly ignored by `.gitignore`.
- `__pycache__/` and `*.pyc`
- `.pytest_cache/`
- `notebooks/.ipynb_checkpoints/`
- Temporary `.txt` log outputs (`final_pytest.txt`, `warnings_output.txt`)
- Temporary HTML files (`social_preview_temp.html`)

## C. Local Runtime Data
SQLite generates temporary `.db-shm` and `.db-wal` files during local execution.
- `test.db`, `test.db-shm`, `test.db-wal` (Root-level SQLite databases generated by `pytest` integration tests)
- `data/cases.db-shm`, `data/cases.db-wal` (Temporary write-ahead logs for the local dashboard)
*Note: These databases are used by local tests and the fallback dashboard mode. While they are safe to delete between runs, doing so resets local demo state.*

## D. Old Architecture & Duplicate-Code Audit
- **Source Folders**: The source architecture has successfully migrated to `src/fraudshield/`. Legacy folders (`src/data`, `src/features`) do not exist.
- **Tests**: Only `tests/` exists; there is no duplicate `test/` directory.
- **Configs**: `config/` holds Docker orchestrator YAMLs (Grafana/Prometheus), while `configs/` holds ML YAMLs. Both are uniquely purposed and actively used.

## E. Dependency File Audit
- **`pyproject.toml`**: The primary dependency source for both local dev and the Dockerfile (`pip install .[api,dashboard]`).
- **`requirements.txt`**: Completely redundant. A `grep_search` confirmed it is not referenced by any CI flow, Dockerfile, or script.

## F. Script Audit
The `scratch/` directory contains numerous one-time development and diagnostic scripts (`ablation_runner.py`, `run_audit.py`, `fix_notebooks.py`).
The `scripts/` directory contains active CI/Release utilities (`capture_release_screenshots.py`, `seed_demo_cases.py`, `create_inference_bundle.py`).
`retry_explanation_screenshot.py` is a one-off debugging script.

## G. Model Artifact Audit
- **`artifacts/runs/`**: Contains older `model.joblib` and PyTorch `.pt` artifacts. These are 10-20MB each and take up the majority of the disk space. They are NOT referenced by active tests (except ablation logic in `scratch/`).
- **`artifacts/final/`**: Contains the active `inference_bundle` as well as `calibrator.joblib` and `preprocessor.joblib`. **Critical Note**: The legacy `.joblib` files must NOT be deleted because they are heavily referenced by `test_inference_parity.py` and `test_bundle_parity.py`.

## H. Notebook Audit
Notebooks (`01_data_validation_and_eda.ipynb`, `02_feature_engineering_and_split.ipynb`, `03_baseline_modeling.ipynb`) are concise (<12KB each) and do not contain heavy embedded graphics or absolute local paths. They remain valuable for scientific storytelling.

## I. Report & Documentation Audit
The `reports/` folder correctly separates exploratory reports from Phase 10 validations and v1 release metrics. No duplicate or contradicted reports exist.
