# Reason Code Dictionary

This dictionary defines the standard reason codes generated by the FraudShield ML Explainability Pipeline. These codes are used to explain why a particular transaction was flagged as high risk. The pipeline uses Integrated Gradients (IG) to calculate feature attributions, which are then mapped to these human-readable reason codes.

## Mapping Logic

Attributions are aggregated from the raw features back to the logical feature groups. If the sum of attributions for a logical group exceeds a predefined sensitivity threshold (e.g., `0.5`), the corresponding reason code is generated.

## Reason Codes

| Reason Code | Logical Feature Group | Trigger Condition | Description |
| :--- | :--- | :--- | :--- |
| `HIGH_AMOUNT` | `amount` | Positive attribution > 0.5 | The transaction amount is unusually high compared to typical patterns. |
| `LOW_SOURCE_BALANCE` | `oldbalanceOrg` | Positive attribution > 0.5 | The source account has an unusually low balance prior to the transaction. |
| `RISKY_TRANSACTION_TYPE` | `type`, `is_risky_type`, `orig_account_type`, `dest_account_type` | Positive attribution > 0.5 | The type of transaction (e.g., CASH_OUT, TRANSFER) or the account types involved carry higher inherent risk. |
| `UNUSUAL_TRANSACTION_TIME` | `step`, `hour_of_day`, `day_of_week` | Positive attribution > 0.5 | The transaction occurred at an unusual time of day or day of week for this customer or in general. |

*Note: Reason codes represent contributing signals to the model's decision, not deterministic "causes" of fraud. The model uses complex non-linear combinations of all features.*
